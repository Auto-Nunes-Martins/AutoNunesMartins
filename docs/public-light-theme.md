# Public light theme

The public light theme uses `--orbit-gray-surface: #e0e0dd` in `apps/website/src/lib/components/stand-concepts/orbitLightTheme.css`.

The owner selected the actual homepage panel “Não vendemos a mesma escolha a toda a gente” as the visual reference. Browser measurement on 2026-10-15 returned `rgb(224, 224, 221)`, opacity `1`, with the full-width box shadow painted in that same color. There is no alpha composition to approximate. Cards, editorial bands, FAQs, fields and other gray panels consume this one token. The owner later requested a navbar-only exception: `--orbit-nav-surface: #f2f2ef`, with a restrained lower shadow. The owner approved this light base and subsequently requested removal of the reflection gradients; the surface is now solid. Desktop navigation stays transparent over that continuous surface; the mobile menu uses the same solid light treatment. This changes neither the common gray token nor navigation geometry or behavior.

The owner subsequently requested an explicit exception for reviews: `--orbit-review-paper: #fafaf7`, a restrained white light gradient and layered edge/shadow relief. The quotation marks were restored to their historical light appearance: `#6b6b70` with opacity `.35`, using the original light `--muted` value from `DesignEdition.svelte` and the `.quote` opacity from `OrbitReviews.svelte` in HEAD and HEAD~1 before these experiments. The color is explicit because the current shared muted palette differs. The review text, names, ratings, illustrative verification labels and structure remain unchanged. This treatment is visible without hover, including on mobile.

The page background is separate: `#f5f5f1`, recovered from the existing `.design.orbit:not(.dark)` base rule in `DesignEdition.svelte`, before the light-theme experiments. Intermediate experimental overrides were `#e5e5df` and then `#e7e7e4`; those were already darker experiments, not the original page background. The original base was restored to satisfy the requested lighter page around the gray components.

Palette rules exclude `.dark`; the explicitly requested hero-3 shadow extension now applies to both themes. Photography, hero framing, fade settings, the map artwork, existing dark contact/footer palettes, business data and publication placeholders are outside this palette change. This is design documentation, not publication approval.

The final hero-3 clarification separates the canvas from the local shadow: `--hero-base` mixes the common gray surface and `--orbit-page-background` 25/75 (approximately `#f0f0ec`); `--hero-copy-shadow` supplies the original dark copy color. This lighter blend is a hero-only exception requested after the shared surface was selected. The copy uses the existing dark-mode gradient/opacity and the light logo/text. The local shadow retains the shared dark gradient, opacity, mask and no blur from `orbitRhythm.css`. A subsequent explicit request extends the hero-3 minimum height in both themes to cover the extra intro space and perspective projection, clipping the decorative overshoot exactly at the intro floor. Content, stage, photographs and their geometry are unchanged; the same decorative extension is shared with dark mode while its gradient, opacity and mask remain unchanged. The stand photos blend laterally against that lighter base. The light hero removes both bottom fade sources: the overlay bottom gradient and the bottom feather in the vertical image mask. Mobile retains its original top gradient but ends transparent below 62%; the image mask retains its top feather and stays opaque through the bottom. Dark-mode fallbacks remain unchanged. The page beyond the hero retains its separate light background. Stand-image geometry, lateral image masks, numeric lateral fade settings, automatic cropping and the ten-second cycle remain unchanged.

The light statistics strip uses a restrained radial brand-red tint at 10% alpha, reduced from the rejected 16% trial and stronger than the original 4%. Its text, numbers and layout are unchanged; dark mode keeps the original 4% treatment.

The theme action is a normal 44px circular icon button, with a destination-specific accessible label and tooltip, rather than switch semantics. The existing change callback and persistence remain intact. Favorites and the telephone CTA keep their appearance. The telephone icon alone repeats the original 520ms rotation gesture within a five-second CSS cycle, resting for 4.48 seconds. This shared animation is confined to the no-preference motion media query; the old automatic JavaScript timer is no longer attached to the navbar.

Client-side navbar flash regression (2026-10-15): each route previously created an independent dark theme state, then restored localStorage in its component onMount. During light navigation, browser samples captured near-white link and theme-button background colors interpolating back to the correct dark foreground, while opacity and font remained stable. The public root layout now owns one theme context, initialized once and consumed by both DesignEdition and PorscheDetailLab. Each SSR layout creates its own instance with the existing dark default; no user state is shared between server requests. Route changes retain the current choice before the new navbar renders. Existing hover, active-link and background transitions remain. The first full-page load still restores localStorage on mount; this fix targets client-side route transitions, not server-side persistence of the preference. Two regression tests cover initialization, persistence, unavailable storage and instance isolation.

The navbar telephone glyph is now 20px on desktop and 18px on mobile (previously 16px and 14px). A -2px optical margin on each side preserves its original horizontal advance, so the CTA box, text and spacing allocation stay stable. The existing five-second icon animation remains in both themes.

The approved final desktop accent is 28 visual degrees, rising to the right and travelling left/down along its original support in the scene/page. A horizontal SVG path and static CSS rotation provide the final angle from server rendering; no onMount geometry calibration, sticky plane or scroll-position compensation remains. Normalized start `0.424`, dash length `0.16` and original reveal rate are retained. The ray scrolls naturally with the hero while the segment advances on that ray, so viewport movement also includes ordinary page scrolling. The track clips red paint/glow at the hero intro floor; the SVG canvas remains at the original stage height. Mobile retains the original markup, path, phase, taper and transforms; reduced motion keeps the static initial line.

Acceptance was checked against a temporary independent continuous cyan guide anchored in normal document flow, calculated from the initial stage geometry rather than the red segment transforms. This control rejected the sticky implementation: after 100px of scroll it separated from the page guide by approximately 88px. The final natural-scene implementation remained visibly overlaid on the guide throughout scroll 0/100/350/800/1200 and the return, including intermediate frames and the 2K viewport. The guide continued below the hero while the red segment remained clipped inside it. The owner explicitly approved this overlaid version and requested removal of the guide. Only the guide and frame probes were then removed; the approved red motion was preserved. Captures and traces remain as QA artifacts. Svelte checking completed without errors or warnings. This is UI approval, not public website publication approval.

A subsequent request slightly strengthens only desktop glyph illumination: the existing moving radial pool grows from 440x380px to 480x420px and its intermediate alpha multiplier increases from .58 to .68 (approximately 17%). The central .98 multiplier, base text color, typography, position and absence of a global text shadow are unchanged. The effect still multiplies the original nearby-light signal; browser checks returned zero illumination when the line was distant. The mobile gradient remains 260x250px with its original .58 intermediate multiplier. The approved StageBackdrop source and the line glow were not changed.

Final boundary verification: only the hero-3 decorative copy pseudo-element is placed on the clipping plane (transform none), avoiding the gap caused by its former negative-Z perspective projection. Its existing gradient, mask and opacity remain. The local clip and desktop accent clipping window end at the statistics top border (904px in the 1440x1000 check), with no uncovered photo strip or overpaint; logo/title rectangles and transforms are identical. Both themes were inspected. The desktop accent outer halo alone changes from 26px/.35 to 30px/.38; the three inner shadows, core stroke and motion are unchanged. Mobile retains the original 26px halo.

Contact hover audit (read-only): native hover on both Ligar agora and Enviar pedido leaves the light background at #e0e0dd because the light override wins the cascade. Dark changes from #ffffff to #e9ede8. The before layer inherits that effective background; no hover rules were changed.
